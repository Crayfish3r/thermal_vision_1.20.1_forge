# Подключение очков Thermal Vision

Minecraft 1.20.1, Forge 47.4.10, official Mojang mappings, Java 17, Gradle 8.8.
Изменения сделаны в существующем checkout; исходные пользовательские изменения сохранены.
Коммит, публикация и push не выполнялись.

## Ассет и движение

Источник: `art/thermal_goggles/thermal_goggles.bbmodel` и две PNG из этой же папки.
Это модель из предыдущего этапа: 88 кубов, тёмный корпус, оливковые детали,
две оранжевые линзы; голова и шлем в геометрии отсутствуют. Размер PNG — 128×128 RGBA.
Входной отдельный Java-экспорт и `motion.json` отсутствовали. Их содержимое получено
из фактически найденного bbmodel: геометрия, UV, pivot и оба сохранённых таймлайна
прочитаны скриптом `export_bbmodel.py`. Геометрия не подменялась.

`ThermalGogglesModel` — адаптированный Java ModelPart-экспорт для 1.20.1.
Пустые стандартные humanoid-узлы нужны конструктору, они не добавляют персонажа.
Одна модель используется и бронёй, и Curios. Для повторного экспорта:

```powershell
python docs/integration/goggles/export_bbmodel.py
```

Иерархия: `head` → `fixed_mount` → `strap`, `mount_hardware`;
`head` → `goggles_hinge` → `bridge`, `left_optic`, `right_optic`.
Неподвижные части остаются на голове. Java-pivot шарнира относительно головы:
`[0, -7.25, -5.6]`, Y вниз, перед — отрицательный Z, 16 пикселей на блок.
Опущенная поза: 0°, поднятая: −100° по локальной X.
BB-позиция pivot: `[0,31.25,-5.6]`, BB-вращение поднятой позы: +100°.

`art/thermal_goggles/thermal_goggles.motion.json` документирует собственную схему,
провенанс и SHA-256 bbmodel. Копия включена в ресурсы JAR для интегратора.
Исходные клипы: опускание 0.25 с, подъём 0.30 с, точный smoothstep.
Java воспроизводит эти значения; изменение документа само по себе не меняет Java-константы.
Разворот сохраняет текущий угол и скорость: до 0.025 с торможения, затем Hermite
с нулевой конечной скоростью и без выхода за диапазон. Остаточная длительность
сокращается по оставшемуся углу. Время — gameTime + partial tick, а не число кадров.
При паузе мира движение стоит. Новая отслеживаемая сущность получает конечную
подтверждённую позу; последующие подтверждения запускают плавный переход.

Текстура выбирается по серверному визуальному состоянию. Она не создаёт собственного
emissive-прохода: яркие линзы являются цветом текстуры. Реальное свечение отдельно не добавлено.

Модель подходит для стандартной головы, второго слоя скина и ванильного шлема.
Габаритные модовые шлемы, нестандартные головы и не-Humanoid рендереры требуют
отдельного адаптера/примерки. Curios-рендерер пропускает неподдерживаемые EntityModel.

## Экипировка и Curios

ID `thermal_vision:thermal_goggles`, ArmorItem-регистрация, рецепты, `ThermalUseTicks`
и существующая серверная логика расхода сохранены. Предмет зарегистрирован один раз.

Без Curios работает обычный слот шлема, его прежние свойства брони, ПКМ,
ручное надевание, vanilla shift-click и раздатчик. Forge IClientItemExtensions
возвращает новую голову-модель и соответствующую текстуру.

С Curios работает функциональный `head`. Данные проекта назначают игроку слот
и тег `curios:head`; сторонний мод для создания слота не нужен. `SET size=1`
без replace объединяется Curios через максимум, поэтому не уменьшает больший
head другого мода. Сохранены косметический слот и переключатель видимости.
Ручное надевание в броню запрещено через Forge canEquip, shift-click не выбирает
броню, ArmorItem.use не надевает шлем. Curios обрабатывает ПКМ функционального
аксессуара и shift-click в своём меню. При занятом head действует штатное поведение
Curios для ПКМ, включая разрешённую самим Curios замену с сохранением предмета.
Раздатчик в этом режиме выбрасывает предмет; он не надевает его в броню.

`ThermalVisionAccess.getWorkingGoggles` возвращает настоящий функциональный ItemStack.
Его используют включение, расход и батарейка. Косметические слоты исключены.
В Curios нет curioTick-расхода и нет атрибутов брони/стойкости, в том числе от
пользовательского attribute NBT. Это также предотвращает бонус от оставшегося legacy-шлема.

Миграция на сервере: legacy-очки в HEAD переносятся в свободный разрешённый
функциональный head, сохраняя весь NBT. Если head занят, очки переносятся в
свободное место инвентаря. При полном инвентаре они остаются в HEAD сохранёнными
и неактивными; миграция повторяется после освобождения места. Чужой аксессуар
не вытесняется, предмет не выбрасывается, заряд не удаляется и не дублируется.

При нескольких head-слотах работает первая функциональная пара очков.
Отображается одна видимая пара с учётом косметической замены. Косметическая пара
имеет поднятую выключенную позу и не предоставляет доступ. Скрытие аксессуара
скрывает модель, а функциональные очки продолжают работать.
В Curios-режиме броневой рендер этих очков подавлен: двойного изображения нет.

## Сеть и жизненный цикл

Протокол канала изменён с 1 на 2: клиент и сервер должны использовать эту сборку.
`GogglesVisualS2CPacket` передаёт entity ID, UUID, наличие очков, подтверждённое
включение, режим и выбранный видимый индекс, плюс признак первоначального снимка.
Чужой заряд и покадровый прогресс не передаются. Пакеты изменений идут
TRACKING_ENTITY_AND_SELF; StartTracking отправляет снимок текущего состояния.
Владелец продолжает получать прежние пакеты заряда/HUD.

Каждая сущность имеет отдельную интерполяцию на клиенте. Смена ItemStack активной
пары отключает режим до расхода заряда новой пары. Снятие, смерть, spectator,
разряд, выход и остановка сервера очищают/выключают соответствующее состояние.
Вход и смена измерения синхронизируют владельца. Клиент очищает визуальные
записи при удалении сущности, смене ClientLevel и отключении.
Модель регистрируется через RegisterLayerDefinitions, лениво запекается после
жизненного цикла EntityModels и пересоздаётся после перезагрузки ресурсов.
Наклоны, приседание и другие позы берутся из уже анимированной головы родителя.
Постпроцесс, HUD и звуки не переписывались ради модели; в reload-listener
добавлено только сбрасывание кэша модели.

## Сборка и запуск

Curios Forge `5.14.1+1.20.1`: compileOnly API, runtimeOnly полный мод только с
`-PwithCurios=true`. Curios и GeckoLib внутрь JAR не включаются. В mods.toml
Curios — необязательная зависимость `[5.14.1,6)` с порядком AFTER, обе стороны.
Если Curios установлен в игре, он должен присутствовать на клиенте и сервере.

```powershell
.\gradlew.bat clean build --console=plain
.\gradlew.bat runClient --console=plain
.\gradlew.bat runServer --console=plain
.\gradlew.bat -PwithCurios=true runClient --console=plain
.\gradlew.bat -PwithCurios=true runServer --console=plain
```

Результат: `build/libs/thermal_vision_v4.jar`.
Для dev Curios включено официальное remapRefMap на `build/createSrgToMcp/output.srg`.
Официальные источники API и данных:

- https://docs.illusivesoulworks.com/1.20.x/curios/getting-started
- https://docs.illusivesoulworks.com/1.20.x/curios/slots/slot-register
- https://docs.illusivesoulworks.com/1.20.x/curios/slots/entity-register
- https://maven.theillusivec4.top/top/theillusivec4/curios/curios-forge/5.14.1%2B1.20.1/

В этой среде первая HTTPS-загрузка API из Gradle завершилась таймаутом.
Неизменённые официальный API JAR, полный JAR и POM загружены отдельно в локальный
игнорируемый Maven-кэш `.gradle/goggles-maven`. При таком же сбое можно использовать
`-I docs/integration/goggles/cache-maven.init.gradle`, который выбирает этот кэш
перед официальным Maven. Сам кэш не включён в git и не является частью зависимости
доставляемого мода. Без заполненного кэша используется обычный официальный Maven.

## Воспроизводимые проверки

`-PgogglesAudit` добавляет только dev-исходники из `runtime/` и изолированные миры
в `build/goggles-audit/{vanilla|curios}/{client|server}`. В обычный JAR аудит не входит.
Для сервера нужна уже принятая EULA в его изолированной папке. При этой проверке
скопирован существующий принятый `run/eula.txt`; пользовательские игровые миры не открывались.

```powershell
.\gradlew.bat -PgogglesAudit runClient --console=plain
.\gradlew.bat -PgogglesAudit -PwithCurios=true runClient --console=plain
.\gradlew.bat -PgogglesAudit runServer --console=plain
.\gradlew.bat -PgogglesAudit -PwithCurios=true runServer --console=plain
```

Для численной проверки `javac -d build/goggles-checks` с двумя файлами:
`src/main/java/com/yourname/thermalvision/client/model/ThermalGogglesMotion.java`
и `docs/integration/goggles/MotionChecks.java`; затем `java -cp build/goggles-checks MotionChecks`.
Она проверяет длительности, исходный easing, C1-разворот, траекторию при 60/960 FPS,
4000 быстрых выборок и паузу. Итоговые результаты, ограничения и доказательства
запусков записаны в `VALIDATION.md`; полный Java diff — `JAVA_DIFF.patch`.
