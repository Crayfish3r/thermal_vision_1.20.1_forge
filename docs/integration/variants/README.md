# Thermal Vision 5.0.0 — White Hot и Night Vision

Платформа: Minecraft 1.20.1, Forge 47.4.10, Java 17.
Артефакт: `build/libs/thermal_vision_v5.jar`.

Добавлены два отдельных предмета: `thermal_vision:thermal_goggles_white_hot`
и `thermal_vision:thermal_goggles_night_vision`. Надеть очки и нажать V.
Обычная батарейка заряжает все три вида. Заряд пока составляет 60 секунд.
White Hot выделяет живые существа белым на сером фоне; Night Vision усиливает
имеющиеся тёмные детали изображения и использует зелёную палитру без тепловой маски.
Это экранное усиление: полностью чёрные пиксели не содержат восстанавливаемых деталей.

Рецепты повторяют расположение ингредиентов исходных очков; центральный блок —
кварцевый для White Hot и изумрудный для Night Vision. Добавлены открытия рецептов,
локализации и объёмные модели предметов в инвентаре.

Геометрия и текстуры взяты из предоставленных `art/thermal_variants/*/modded_entity`:
88 кубов White Hot и 51 куб Night Vision. Использована предназначенная для Java
Box UV версия; её зерно на линзах отличается от Free Model, как описано автором
в README исходных моделей. Поднятие визора использует существующую анимацию шарнира.

## Изменения Java

Полный diff, включая новые Java-файлы: [JAVA_DIFF.patch](JAVA_DIFF.patch).

- `VisionMode`: три режима с фиксированным порядком сетевого кодирования, определение режима по предмету.
- `ThermalImagerAccessoryItem`: режим устройства, выбор текстуры по стеку, пояснение Night Vision.
- `ModItems`: регистрация двух новых очков и общий признак подходящего предмета.
- `ThermalVision`: добавление новых предметов в творческие вкладки.
- `ThermalEquipment`: распознавание всех трёх моделей в слоте головы.
- `CuriosEquipment`: регистрация, поиск и перенос всех трёх устройств в Curios.
- `ServerThermalVisionStates`: обработка уничтожения любого вида очков.
- `SetThermalVisionS2CPacket`: передача серверного режима вместе с зарядом и активацией.
- `ModNetworking`: определение режима из серверного слота и повышение версии протокола до 3.
- `ClientNetworkHandlers`: передача подтверждённого режима клиентскому состоянию.
- `ClientThermalVisionState`: сохранение режима при затухании, сброс эффекта при смене режима.
- `ThermalGogglesClient`: отдельные запечённые модели и текстуры, общее очищение кэша при reload.
- `WhiteHotGeometry`, `NightVisionGeometry`: полная экспортированная геометрия исходных моделей.
- `CuriosGogglesRenderer`: выбор модели по отображаемому стеку, включая косметический слот.
- `ThermalVisionPostProcessor`: установка и проверка uniform VisionMode.
- `ThermalVisionRenderPipeline`: белая палитра композитинга, исключение тепловой маски для Night Vision.
- `ThermalVisionWorldRenderer`: поиск и оранжевые ореолы блоков работают только в исходном тепловом режиме.
- `ThermalVisionHudOverlay`: название активного режима; Night Vision не показывает радиус обнаружения существ.
- `GogglesClientAudit`: дополнительные игровые сценарии двух разновидностей и снимки экрана; в JAR не включён.

## Проверки и ограничения

Успешная чистая сборка:

```
.\gradlew.bat -I docs/integration/goggles/cache-maven.init.gradle clean build --console=plain
```

Обычная сборка завершилась ошибкой загрузки Curios из Maven по HTTPS-тайм-ауту.
Успешная сборка использует имеющийся локальный кэш проекта.
Проверены соответствие всех исходных ресурсов содержимому JAR, JSON, наличие
Java 17 классов, версия 5.0.0, отсутствие игровых audit-классов и `git diff --check`.
Контрольная сумма находится в `artifact-check.txt`.

Игровой клиент не запускался: автоматическая проверка разрешения запуска
не завершилась из-за лимита использования. Пользователь затем попросил не запускать
ручные тесты. Компиляция GLSL драйвером, внешний вид в игре и игровые сценарии
новых вариантов пока не подтверждены. Совместимость с внешними шейдерпаками и
нестандартными living-renderer также не проверена.

Это сборка этапа добавления разновидностей. Настраиваемый серверный конфиг и
дальнейшее профилирование из первоначального плана ещё не реализованы.
Клиент и сервер должны использовать обновлённый сетевой протокол.
